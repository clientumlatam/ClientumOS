The root wires together several child modules into a single deployable unit: `index.ts` is the Vercel serverless entry that bootstraps the Express `app` from `server.ts`, runs idempotent DB table initialisation (`initUsersTable`, `initChatbotLeadsTable`, `initSantiTables`), and exports the app as a handler. `server.ts` is the monolithic API layer — it owns all Express middleware (session with `connect-pg-simple` against PostgreSQL, JWT-free cookie sessions, role-based `requireAuth`/`requireAdmin`, API-key and CRM-token middleware) and registers every `/api/*` route in one file. The Vite dev server (`vite.config.ts`) serves the React SPA while `tsx server.ts` runs the backend concurrently; production builds bundle the SPA with Vite and transpile `server.ts` to CJS via esbuild. Cross-child wiring points: `scripts/` provides `setup-env.js` invoked by `npm run setup:env` (pre-dev hook) to bootstrap `.env`; `firebase-applet-config.json` and `firestore.rules` configure the Firebase client-side SDK used by the `app_shell`; `tooling_config/` holds Refact agent definitions consumed by the same runtime. The `assets_and_public/` directory is purely attached artifacts and does not participate in the build.
