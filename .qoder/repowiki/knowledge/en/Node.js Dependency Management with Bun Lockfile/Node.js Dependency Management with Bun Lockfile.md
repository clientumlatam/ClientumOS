This repository manages dependencies through a single `package.json` at the project root using npm-style declarations, with a `bun.lock` lockfile pinning exact transitive dependency versions. The project is a monorepo-style full-stack app (React + Express) but uses a flat dependency structure rather than workspaces.

**System and tools used:**
- `package.json` declares runtime `dependencies` and `devDependencies` using caret (`^`) version ranges for most packages, indicating flexibility to install minor/patch updates within the specified major version.
- `bun.lock` is committed and serves as the deterministic lockfile; it records every resolved package with its exact version and integrity hash, ensuring reproducible installs across environments.
- No `node_modules` directory is present in the tree, confirming that Bun resolves dependencies from the lockfile without vendoring source code into a local `vendor/` or `node_modules` folder checked into git.
- `replit.nix` pins OS-level system dependencies (`psmisc`, `mysql80`, `unzip`) for the Replit environment, separate from Node.js dependencies.
- A separate `skills-lock.json` tracks AI agent skill definitions sourced from GitHub repositories, each entry including a `computedHash` to ensure skill content integrity — this is an auxiliary dependency manifest for non-code assets.

**Key files:**
- `package.json` — primary dependency manifest with all runtime and dev dependencies declared.
- `bun.lock` — deterministic lockfile generated by Bun, containing the full resolved dependency graph with SHA hashes.
- `skills-lock.json` — lockfile for AI agent skills pulled from external GitHub sources.
- `replit.nix` — Nix-based system-level dependency declarations for the Replit platform.

**Architecture and conventions:**
- All third-party libraries are declared centrally in `package.json`; there is no per-module or per-package dependency file.
- Version ranges use `^` for most packages, allowing automatic patch/minor updates while constraining major versions.
- The build pipeline uses `vite build` for the frontend and `esbuild` for bundling the Express server (`server.ts`), with `tsx` used for development-time TypeScript execution.
- Environment setup is automated via `scripts/setup-env.js` invoked through the `predev` npm script hook, ensuring `.env` configuration runs before development.
- Secrets and environment variables are managed through scripts (`scripts/pull-secrets.mjs`, `scripts/sync-secrets.mjs`) that synchronize values between Replit, Vercel, and GitHub.

**Constraints and rules observed:**
- The lockfile `bun.lock` is committed, enforcing deterministic dependency resolution across all environments.
- System dependencies for the Replit environment are explicitly pinned in `replit.nix` rather than installed ad-hoc.
- Agent skills are tracked separately in `skills-lock.json` with computed hashes, preventing drift in referenced skill content.
- No private npm registry or custom `.npmrc` configuration is visible; dependencies are resolved from the public npm registry.
